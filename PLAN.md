# WEST time and timer — план
Обновлено 21 сентября 2026. **Локальная реализация и Xcode-сборка завершены; публикация не выполнялась.** Утверждённый бело-фиолетовый дизайн реализован, русский добавлен одиннадцатым языком. Только macOS desktop; другие платформы не входят в объём. [Промпт реализации](PROMPT.md), [исследование](RESEARCH.md), [фактическая проверка](docs/VERIFICATION.md).

## Продукт
Небольшое нативное macOS-приложение: один таймер, список мировых часов и два настоящих WidgetKit-виджета для рабочего стола и Центра уведомлений. Название: **WEST time and timer**. Предлагаемый slug: `west-time-and-timer`; доступность имени не проверена.

Одно окно: таймер сверху, часы ниже; добавление часов в sheet, компактные настройки. Без аккаунтов, сети, аналитики, синхронизации, секундомера, будильников, Pomodoro, истории, карты, плавающих окон и отдельного меню в строке macOS. Сигнал завершения — часть таймера.

Предлагаемая минимальная система — **macOS 15**: нужный API динамического времени доступен с этой версии. Поддержка более старых систем не входит в текущий объём.

## Часовые пояса
Города и обозначения поясов — независимые типы записей. Berlin и отдельный CEST могут одновременно находиться в списке и виджете, даже с одинаковым временем. Каждая запись имеет собственный ID, тип, IANA ID, название города либо данные сезонной пары и порядок. Не объединять записи по IANA ID или совпадению смещения. Все часы автоматически следуют правилам региона. Фиксированный режим и переключатель «Авто/Фикс.» удалены.

- Поиск по городу, стране, IANA ID и CET/CEST, EET/EEST, WET/WEST. Небольшой локальный каталог основных городов и синонимов. Системный список зон не является каталогом всех городов мира.
- В добавлении — категории «Города» и «Обозначения поясов» с единым поиском. CEST предлагает отдельный пояс без обязательного выбора города; Berlin, Paris, Rome выводятся отдельно. Поиск обоих сезонных обозначений работает круглый год. Для отдельного CET/CEST используются явные правила Europe/Berlin, EET/EEST — Europe/Helsinki, WET/WEST — Europe/Lisbon; правило показывается при добавлении/в деталях. Это выбранные регионы, не универсальные правила всех стран.
- После выбора Berlin сохраняется Europe/Berlin: летом CEST, зимой CET. Lisbon: WEST/WET; Helsinki: EEST/EET. Системная база определяет переходы; даты DST вручную не задаются.
- UTC-смещение видно в карточке. Запрос UTC+02:00 фильтрует регионы по **текущему** смещению, но выбранный регион продолжает сезонные переходы. Создания постоянного смещения нет.
- Неоднозначные сокращения требуют выбора региона; неизвестное обозначение не превращается в придуманную зону.
- До шести записей: добавить, удалить, переставить; город и соответствующий пояс допустимы одновременно и удаляются независимо. Для города главный заголовок — город; для пояса — текущая аббревиатура (CEST летом, CET зимой). Не подписывать зимнее время как CEST. В карточке время, актуальное обозначение, полное UTC-смещение и разница относительно Mac; при необходимости дата.
- «Показывать секунды в часах» — общая настройка окна и виджетов, по умолчанию выключена. Формат System/12/24, по умолчанию System. Таймер всегда показывает секунды.

## Разница относительно Mac
Возле каждой записи в окне и любом виджете показывать +1 ч, −3 ч, 0 ч или +5 ч 30 мин/+5 ч 45 мин с локализацией. Плюс — впереди Mac, минус — позади. Формула для одного текущего момента: UTC-смещение выбранной зоны минус UTC-смещение текущей системной зоны. Не округлять до целых часов, не вычитать только часы на циферблате, не путать с собственным UTC-смещением записи.

Разница вычисляется заново при DST обеих зон и смене системной зоны Mac. Не хранить её постоянным числом. Пример при Europe/Lisbon летом: Berlin и CEST имеют +1 ч, WEST — 0 ч. Для производных подписей проверить динамическое форматирование или необходимые timeline-переходы/системные обновления. Отдельная runtime-проверка — смена системной зоны при завершённом приложении: currentDate сам по себе не доказывает обновление сохранённых параметров зоны.

## Таймер
Один общий таймер для окна и всех его виджетов. Ввод часов/минут/секунд, диапазон 1 секунда — 23:59:59, пресеты 5/15/25/60 минут, исходно 25 минут.

Состояния: idle → running ↔ paused → finished. Старт, пауза, продолжить, сброс, повтор. Во время отсчёта изменение длительности требует сброса. На нуле остановка, без отрицательных значений и счёта вверх.

Хранить исходную длительность, абсолютный дедлайн, остаток на паузе, ID запуска и версию. Остаток вычислять по времени, не декрементировать сохранённое число callback-ами. Закрытие окна, выход, сон и повторный запуск не сбрасывают отсчёт. Истёкший дедлайн трактуется как finished при чтении состояния. Сон входит в длительность; приложение не будит Mac. Смена только часового пояса не меняет остаток. Для простоты ручная коррекция системных часов меняет остаток относительно абсолютного дедлайна; это документируется.

Одно локальное уведомление со стандартным звуком. При паузе/сбросе отменить, при продолжении перепланировать; восстановление не создаёт дубликат. Разрешение запросить при первом старте из приложения; из виджета дать путь к настройке в приложении. Отказ не блокирует таймер. Не обещать звук во сне или обход Focus.

## Живые часы
Основное решение: SwiftUI `Text` с **`TimeDataSource.currentDate`** и `Date.FormatStyle`, настроенным на IANA-зону. Источник обслуживается системой, приложение не должно постоянно работать. Секунды включаются/исключаются форматом. Доступность с macOS 15 и соответствие форматов DiscreteFormatStyle проверены в локальном SDK. [Apple: TimeDataSource](https://developer.apple.com/documentation/swiftui/timedatasource), [SystemFormatStyle](https://developer.apple.com/documentation/swiftui/systemformatstyle).

Дата, аббревиатура и смещение тоже должны зависеть от текущего системного времени, а не оставаться строками из entry.date. Проверить обязательные латинские сокращения во всех локализациях; допустимы небольшие отображаемые алиасы поверх системных данных, без собственных DST-правил.

Timeline нужен для конфигурации и переходов состояния. Reload после пользовательских изменений, не каждую секунду. Никаких тысяч записей, фонового демона или NTP. Таймер — системный динамический countdown с ограниченным интервалом, остающийся на нуле. Отдельно проверить задержку смены кнопок/подписи завершения: обновление цифр не гарантирует пересоздание всего виджета в тот же момент.

**Runtime-проверка на реальном Mac:** приложение и разные зоны проверены; все четыре варианта расширения обнаруживаются системной галереей, превью таймера отрисовывается. Добавление виджетов на рабочий стол, сон/пробуждение и смена системного времени при закрытом приложении остаются отдельными проверками. macOS управляет частотой отрисовки, особенно при энергосбережении; не обещать физическую перерисовку каждую секунду во всех состояниях. Значение должно вычисляться из актуального времени macOS.

Виджеты:
- Таймер small: старт выбранной длительности, пауза/продолжить, сброс, повтор через App Intents. Все экземпляры управляют одним таймером.
- Часы small: одна запись; medium: до трёх; large: от одной до шести одновременно, без прокрутки и страниц. В каждой строке разница относительно Mac. Допустима смесь городов и поясов, включая Berlin и CEST. По умолчанию общий список и порядок; конфигурация выбирает сохранённые записи в пределах размера. Шесть строк читаемы с секундами, длинными именами и RTL. Пустое состояние открывает добавление, удаление выбранной записи просит перенастройку.
- Пользователь добавляет виджеты средствами macOS. Геометрия и тонирование подчиняются WidgetKit; размеры на концептах ориентировочные.

## Простая архитектура
Один Xcode-проект: приложение SwiftUI и Widget Extension, общие Swift-файлы подключены к обоим target, один тестовый target. **Отдельный Swift Package не нужен.**

Системные SwiftUI, Foundation, WidgetKit, AppIntents, UserNotifications; AppKit только при необходимости. Без стороннего UI-фреймворка, БД, DI-контейнера и многоуровневой архитектуры.

Общие данные в App Group: небольшой Codable-файл с атомарной записью и межпроцессной координацией. Actor внутри одного процесса недостаточен. Общий обработчик команд окна и App Intents: перечитать, проверить ID запуска/версию, изменить, сохранить, согласовать уведомление и обновить виджеты. Повторные и устаревшие команды безопасны. Хранилище не переписывается ежесекундно.

Новые требования отдельных поясов, шести часов и разницы относительно Mac имеют приоритет над прежним макетом.

## План работ и приёмка
1. **Проверка системного времени.** Реальный widget на macOS 15+: динамические секунды, зоны, дата/DST, ограниченный countdown. При проблемах уточнить решение до основной реализации; не выдавать устаревающие снимки за живые часы.
2. **Модели и хранение.** Поиск, независимые записи городов/поясов, таймер, App Group и общие команды. Проверить независимое удаление Berlin/CEST, шесть записей в виджете, разницу относительно Mac и зоны с несовпадающими датами DST. Тесты обоих DST-переходов для Lisbon/Berlin/Helsinki, +05:30/+05:45, полуночи, неизвестных запросов, дедлайна/паузы/повтора, испорченных данных и конфликтующих команд.
3. **Окно в выбранном дизайне.** Все состояния часов и таймера, настройки, уведомления, 11 локализаций, пустые состояния и доступность.
4. **Виджеты и интеграция.** App Intents, конфигурация, несколько виджетов и окно, завершённое приложение, сон, перезапуск, дата/зона, отказ в уведомлениях, тонирование, RTL. В отчёте разделить выполненные и невыполненные проверки с версиями macOS/Xcode. Компиляция для минимальной ОС не заменяет запуск на ней.
5. **Публичный репозиторий.** README на английском с реальными скриншотами, MIT с подтверждённым правообладателем, notices для заимствований, .gitignore, общие schemes, пример локальных signing settings, краткие docs сборки/проверки/релиза. Минимальный macOS CI: тесты и сборка без подписи, где применимо. Проверить текущие файлы и историю на секреты/персональные данные; историю самовольно не переписывать.
6. **Устанавливаемый DMG — обязательный результат.** Для выбранного локального сценария собран arm64 DMG с вложенным расширением, ad-hoc подписью и ссылкой Applications; проверены образ, SHA-256 и строгая deep-проверка подписи. Developer ID, notarization/stapling, universal-сборка и проверка скачанного quarantine-файла на другом Mac относятся только к будущему публичному распространению и не входят в текущий локальный выпуск.
7. **GitHub Release.** Тег v1.0.0, DMG, SHA-256, release notes, требования macOS, инструкция «скачать → DMG → Applications → запустить → добавить виджет». Пользователю не нужны Xcode, Homebrew и зависимости. Обычное подтверждение первого открытия возможно; отключение Gatekeeper не является штатной установкой. Публикация выполняется в рамках будущего запроса на выпуск, сейчас ничего не публикуется.

Для первого релиза достаточно воспроизводимого локального скрипта упаковки и загрузки проверенного DMG. Сложная инфраструктура подписи в CI не нужна. Сертификаты, ключи, credentials, пользовательское состояние и личные абсолютные пути не попадают в Git. Публичные Bundle/App Group ID сами по себе не секреты; конфигурация должна позволять сборку другой командой.
