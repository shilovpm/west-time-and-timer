# Промпт будущей реализации WEST time and timer
Обновлено 18 сентября 2026. Сейчас выполняется только проектирование; этот промпт предназначен для отдельного запуска реализации. Дизайн B и русский язык согласованы.

---

Создай небольшое нативное приложение **WEST time and timer** только для **macOS desktop 15+**. Основные функции: мировые часы, один таймер и настоящие системные виджеты. Выполни реализацию, проверки и подготовку устанавливаемого DMG. Не разрабатывай версии для iPhone, iPad, Windows, Android или браузера.

**Дизайн и интерфейс**

Выбран вариант **B — Material 3**, референс: `design/B-material-soft.png`. Мягкие карточки, фиолетовые акценты, округлые кнопки, круговой индикатор таймера, чёткие цифры. Реализуй эту стилистику средствами SwiftUI и SF Symbols, без стороннего UI-фреймворка. Сохрани привычное поведение macOS, системные светлую/тёмную темы, клавиатуру, VoiceOver и хороший контраст.

Одно главное окно: таймер сверху, список часов ниже. Добавление часов — sheet, настройки — компактное окно. Макет определяет стиль; новые требования ниже имеют приоритет: отдельные записи обозначений, до шести часов в одном виджете и разница относительно времени Mac. Не копируй случайные декоративные буквы из макета.

Не добавляй секундомер, будильники, Pomodoro, несколько таймеров, аккаунты, аналитику, сервер, синхронизацию, карту, историю, плавающие окна или отдельное меню в строке macOS. Приложение работает без интернета.

**Мировые часы: города и обозначения — отдельные записи**

Пользователь может одновременно добавить **Berlin** и **CEST**: это две независимые строки, даже если сейчас они показывают одинаковое время. Не объединяй записи по совпадению IANA-зоны или UTC-смещения.

В добавлении часов предусмотрены категории «Города» и «Обозначения поясов» с единым поиском. Поиск CEST показывает отдельный результат пояса, который можно добавить без выбора города; города выводятся отдельно. Поддержи поиск по городу, стране, IANA ID, CET/CEST, EET/EEST и WET/WEST. Небольшой локальный каталог основных городов и синонимов; не обещай все города мира.

Все записи используют **только автоматические сезонные правила конкретной IANA-зоны**:
- CET/CEST — правила Europe/Berlin;
- EET/EEST — Europe/Helsinki;
- WET/WEST — Europe/Lisbon.

Для отдельного пояса главным названием служит актуальная аббревиатура, а не город. Покажи в добавлении/деталях сезонную пару и используемые региональные правила. Например, летом отдельная строка называется CEST, зимой автоматически CET; поиск по обоим обозначениям доступен круглый год. Это выбранные региональные правила, не утверждение об одинаковых правилах всех стран с таким сокращением. Не показывай зимнее время под ложной летней подписью CEST. Фиксированный режим не добавляй.

Храни уникальный ID записи, тип представления «город/пояс», IANA ID, данные названия города либо сезонной пары и порядок. Удаление Berlin не удаляет отдельную запись CET/CEST. Дубликат точно той же записи можно не создавать, но город и соответствующий пояс обязательно могут сосуществовать.

До шести записей в общем списке: добавление, удаление, перестановка. В каждой строке — название, текущее время, актуальная аббревиатура, UTC-смещение и разница относительно Mac. Для города показывай город главным названием; для пояса — аббревиатуру. Не дублируй одинаковые подписи без необходимости.

Ввод UTC+02:00 — фильтр по текущему смещению, не создание постоянного смещения. Неоднозначные сокращения требуют явного выбора региональных правил; неизвестные запросы не превращаются в придуманные зоны. DST определяется системной базой macOS, без самописного календаря переходов.

**Разница относительно системного времени**

Возле каждой записи в окне и виджете показывай, насколько её время опережает или отстаёт от текущего локального времени Mac: `+1 ч`, `−3 ч`, `0 ч`, `+5 ч 30 мин`, `+5 ч 45 мин`. Подписи локализуются. Плюс означает «впереди Mac», минус — «позади Mac». Нулевая разница видна явно.

Расчёт для одного и того же текущего момента:
`разница = UTC-смещение выбранной зоны − UTC-смещение текущей системной зоны`.

Не путай её с собственным UTC-смещением зоны; не вычитай только числа часов на циферблате и не округляй дробные часы. Разница должна корректно меняться при DST любой из двух зон и при смене системной зоны Mac. Не сохраняй её как постоянное число.

Пример при системной зоне Europe/Lisbon летом: Berlin и отдельный CEST показывают +1 ч, отдельный WEST — 0 ч. При смене системной зоны пересчитываются все строки; выбранные часы сохраняются.

**Настоящие виджеты macOS**

Два типа WidgetKit-виджетов для рабочего стола и Центра уведомлений:
- «Таймер», small: старт выбранной длительности, пауза/продолжить, сброс, повтор.
- «Мировые часы»: small — одна запись, medium — до трёх, **large — от одной до шести записей одновременно**, без прокрутки и переключения страниц.

Большой виджет обязан вместить шесть читаемых строк, включая секунды при включённой настройке и разницу у каждой записи. В одном виджете допустима смесь городов и обозначений, в том числе Berlin и CEST вместе. По умолчанию используй общий список и его порядок; конфигурация виджета позволяет выбрать сохранённые записи в пределах его размера.

Все экземпляры таймера управляют одним общим отсчётом. Произвольная длительность редактируется в приложении. Пустой список даёт путь к добавлению часов; удалённая выбранная запись не заменяется молча другой.

Размеры, фон и тонирование подчиняются WidgetKit. Пользователь добавляет виджеты стандартным способом macOS. Проверь все размеры, шесть строк, длинные названия и RTL.

**Актуальное время и секунды**

Основной механизм часов — SwiftUI Text с `TimeDataSource.currentDate` и `Date.FormatStyle` выбранной TimeZone. Минимальная macOS — 15. Сначала проверь решение на реальном виджете при полностью завершённом приложении.

Дата, аббревиатура, UTC-смещение и разница относительно Mac должны соответствовать текущему моменту. Динамические цифры не должны соседствовать с устаревшими сезонными подписями. Для производных подписей используй поддерживаемое динамическое форматирование либо необходимые timeline-переходы и системные обновления. Проверь отдельно смену системной зоны при закрытом приложении; не считай, что currentDate автоматически решает обновление всех сохранённых параметров.

Не используй ежесекундные reloadTimelines, тысячи снимков, собственную фоновую службу или сетевую синхронизацию времени. Timeline/reload нужны для конфигурации, команд и значимых изменений времени/зоны. macOS управляет частотой отрисовки; не обещай гарантированную перерисовку каждую секунду во всех режимах энергосбережения.

Настройки: «Показывать секунды в часах» on/off, по умолчанию off; применяется к окну и всем виджетам. Формат System/12/24, по умолчанию System. Таймер всегда показывает секунды.

**Таймер**

Один отсчёт, длительность от 1 секунды до 23:59:59, ввод часов/минут/секунд, пресеты 5/15/25/60 минут, исходно 25 минут. Старт, пауза, продолжить, сброс, повтор. Состояния idle/running/paused/finished. Во время работы изменение длительности требует сброса.

Сохраняй исходную длительность, абсолютный дедлайн, остаток на паузе, ID запуска и версию состояния. Остаток вычисляй от дедлайна, не уменьшай сохранённый счётчик callback-ами. Ноль означает остановку: без отрицательных значений и счёта вверх. В виджете используй динамический countdown с ограниченным интервалом.

Закрытие окна, выход, сон и повторный запуск не сбрасывают таймер. Сон входит в длительность, истёкший дедлайн сразу трактуется как finished. Смена только часового пояса не влияет на остаток. Ручная коррекция системных часов может изменить остаток относительно абсолютного дедлайна; документируй эту семантику.

Одно локальное уведомление со стандартным звуком. При первом старте из приложения запроси разрешение; отказ не блокирует отсчёт. При паузе/сбросе отменяй, при продолжении перепланируй, при восстановлении не дублируй. Проверь работу уведомлений из контекста App Intents. Не обещай пробуждение Mac, звук во сне или обход Focus. Статус разрешения в настройках — реальный системный статус и путь к настройке разрешений.

**Языки**

Обязательны **11 языков**: английский, китайский с упрощённой письменностью, хинди, испанский, арабский, французский, бенгальский, португальский, индонезийский, урду и русский.

По умолчанию — первый поддерживаемый язык из системных предпочтений; иначе английский. В настройках System и ручной выбор. Используй String Catalog для окна, виджетов, App Intents и уведомлений. Проверь длинные переводы, арабский/урду RTL, числа, даты, знаки разницы и смешанные строки с латинскими аббревиатурами. Обозначения CET/CEST и подобные не переводятся.

**Простая архитектура**

Один Xcode-проект: SwiftUI app, Widget Extension и один test target. Общие Swift-файлы подключены к обоим продуктовым target. Используй Foundation, WidgetKit, AppIntents, UserNotifications и App Group. Отдельный Swift Package, сторонний UI-фреймворк, БД и многоуровневая архитектура не нужны.

Общие данные — небольшой Codable-файл App Group с атомарной записью и межпроцессной координацией. Единый обработчик команд для окна и App Intents перечитывает состояние, проверяет ID запуска/версию, сохраняет результат и согласует уведомление/обновления. Actor внутри одного процесса не заменяет межпроцессную защиту. Повторные и устаревшие команды безопасны. Не записывай состояние каждую секунду.

Из изученных репозиториев заимствуй только подходящие идеи и небольшие проверенные фрагменты с соблюдением лицензий; не объединяй целые приложения. Подробности — в RESEARCH.md.

Компиляция для минимальной ОС не заменяет запуск на ней. Разделяй пройденные, проваленные и невыполненные проверки, указывай macOS/Xcode.
